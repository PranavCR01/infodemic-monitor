Interactions

  • Timeline segment click → video.currentTime = claim.start, play, scroll the claim card into view, give it the active ring.
  • During playback the card whose range contains currentTime is active; the transcript line too. Throttle to 4 Hz.
  • Claim card click / Enter → open Claim detail drawer, push ?claim=. Esc closes and returns focus to the card. Prev/next arrows move between claims.
  • Transcript timestamp → seek. Highlight colour follows the claim's verdict hue; toggle hides highlights.
  • Jobs row → whole row is one link to /videos/[id].
  • Upload: client checks type (MP4/MOV), size ≤ 100 MB and duration ≤ 3:00 (read from a <video> element's metadata) before upload starts.
  • Export opens /export in a new tab; same data, print stylesheet, Letter.

Polling (no websockets)

  • Job page: GET /jobs/[id] every 3 s for the first 3 min, then every 10 s. Stop on Completed, Needs review or Failed, then router.refresh() to render the result.
  • Pause when document.hidden; poll immediately on visibilitychange and focus.
  • 3 failed polls in a row → “Lost connection” banner, back off 3 → 10 → 20 s.
  • Jobs list: every 10 s only while a visible row is Queued, Running or Retrying.
  • Review queue: every 30 s. If the open item is decided by someone else, show “Already decided by L. Haddad” and disable the form.
  • Suggested: SWR or TanStack Query refetchInterval as a function of state.

Collapsed by default

  • Critic's notes (claim detail)
  • “How the video label is reached” (result)
  • Audit trail on tablet (expanded on desktop)
  • Supports list when it is empty (one line instead)
  • Everything else is open: analysts must see the evidence without clicking.

“What this means” line: stance × verdict

Shown on the deciding claim (and on hover/focus for others). Fixed copy from this table, never model output. This is the main guard against reading DEBUNKED as MISINFO.

StanceCONTRADICTEDSUPPORTEDINSUFFICIENT / MIXED / NOT VERIFIABLE
ENDORSESThe speaker promotes a claim that the evidence contradicts.The speaker states a claim the evidence supports.The speaker promotes a claim no study settles.
REFUTESThe speaker refutes a claim the evidence contradicts. This corrects misinformation.The speaker denies a claim the evidence supports.The speaker refutes a claim no study settles. A reviewer decides.
QUOTESThe speaker reports someone else making a false claim.The speaker reports someone else's supported claim.The speaker reports a claim no study settles.
NEUTRAL / UNCLEARThe speaker's position on this claim is not clear.

Weak spots in this design (decide before building)

  1. Timeline colour on DEBUNKED videos. Markers are coloured by verdict, so a debunk video shows rust CONTRADICTED markers next to a teal DEBUNKED label. The header and the “corrects misinformation” line carry the meaning; test this with 3–5 analysts before launch.
  2. Source counts invite vote-counting. “2 contradict · 1 supports” reads as 2–1 even if the 1 is a systematic review. Cards show the strongest study type beside the count, and evidence is ordered by study type. Consider dropping counts if analysts misread them.
  3. Correcting a claim doesn't recompute the label. Simpler and auditable, but the reviewer can save an inconsistent pair. The panel warns; it doesn't block.
  4. “Not required” review status is a fifth value not in the brief's vocabulary. Needs backend agreement.
  5. Placeholder content. Claim 2/3 quotes, source passages, Evaluation figures and model IDs are invented or bracketed; swap for real API data.

Accessibility checklist

  • Every label, verdict, stance and status = icon + text; icons aria-hidden.
  • Timeline segments are links with aria-label “Claim 1, 0:03 to 0:08, contradicted”.
  • Drawer: role=dialog, focus trap, Esc closes, focus returns.
  • Progress: aria-live=polite on the current step name only, not the timer.
  • Tables: th scope, aria-sort on sorted column.
  • Reduced motion: no spinner rotation, no smooth scroll.
  • Dark mode: system preference by default, user override stored in a cookie for SSR.
  • Export: prints in greyscale; label name is always printed.
